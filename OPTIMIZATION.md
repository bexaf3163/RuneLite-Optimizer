# Проверка устойчивых 60 FPS

60 FPS — бюджет 16,667 мс на кадр. Средние 90 FPS могут сопровождаться зависаниями: нужны p95/p99, 1% low, число интервалов >33/50/100 мс и несколько повторов. p99 не описывает худший 1% целиком; 1% low не является минимальным мгновенным FPS. Длинные интервалы не удаляются. Даже хороший короткий тест не гарантирует отсутствие всех будущих зависаний.

## Процедура

1. Зафиксировать рендерер, мир, размер окна/разрешение, место, ракурс. Прогреть сцену 30–60 секунд; холодную загрузку проверять отдельно.
2. При закрытой игре применить тестовый профиль 999. Запустить RuneLite обычным способом. Проверить Unlock FPS / VSync / FPS Control / драйверный лимит в самом клиенте. Флажок в оптимизаторе только отмечает условия.
3. GE, центр Varrock, Falador, Lumbridge — по 120 секунд, желательно 3 повтора. Отдельно неподвижная камера и движение по одинаковому участку. Во время сбора держать игру активной.
4. Сохранить базовый проход. Изменять одну группу настроек и повторять условия в том же режиме лимита. Большее число кадров не компенсирует разные сцены.
5. Вернуть 60 и повторить все сцены. Тест запаса при 999 не заменяет проверки ритма кадров при 60.
6. Сохранить отчёты. Сопоставить медиану повторов, p99, 1% low и число задержек на одинаковую длительность. Не выбирать настройки по одному удачному проходу.

## Проверяемые гипотезы

| Наблюдение | Следующая отдельная проверка |
|---|---|
| FPS низкий постоянно, особенно HD | Сначала отключить тени, затем отдельно MSAA |
| Сильнее падает в толпе | HD detail distance, затем отдельно общая дальность |
| Пики при границах карты | Сравнить expanded map loading 0 и 1 на одном маршруте: дополнительная загрузка может и помочь, и усилить нагрузку |
| Хуже при большом окне | Сравнить разрешение сцены; выигрыш поддерживает гипотезу графического ограничения, но не измеряет GPU load |
| Ступени 60/30 | Проверить VSync и дополнительные лимитеры |
| Редкие остановки независимо от качества | Сравнить прогретую сцену и фоновую нагрузку штатными средствами; не объявлять Java GC или перегрев без доказательств |

Пользу подтверждает повторяемое уменьшение p95/p99 и задержек при сопоставимых условиях, а не только рост среднего FPS.

## 117 HD и этот компьютер

Стартовый профиль отключает тени/MSAA, уменьшает обе дальности и расширенную загрузку, сохраняя разрешение 100%. Картинка становится проще. Если цель держится — возвращать качество по одной группе. Если нет — отдельно сравнить разрешение сцены, затем вручную Standard GPU как альтернативный рендерер.

На обнаруженной интегрированной Iris Xe полезно в первую очередь проверить стоимость теней и высокого разрешения. Это гипотеза, не измеренный прирост. Большой map loading и legacy cache не стоит автоматически повышать «для ускорения». Экспериментальные обходы драйвера и внутренние буферы меняются только по отдельной причине.

Сетевой лаг не обязательно влияет на FPS. Оптимизатор не управляет персонажем, не определяет населённость мира, не переключает плагины, не правит реестр/службы и не снимает лимит незаметно в активной игре. Автоматический подбор потребует подтверждённых игровых измерений и надёжного определения активного рендерера/сцены.
